# Arsenal · 百器库

**把常用的 AI 技能收进一个工具库，在不同工具和项目中按需使用。**

Arsenal 是一款面向 AI 技能的桌面管理软件。它把技能收集、分组整理、安装、来源更新和使用笔记放在同一个界面中，让你知道收藏了什么、装到了哪里，以及哪些内容值得更新。

## 为什么使用 Arsenal

收藏技能不难，难的是在需要时找到它，知道它适合哪个任务，并在不同 AI 工具之间保持一致。

| 你遇到的问题 | Arsenal 提供的方式 |
| --- | --- |
| 技能散落在 GitHub、下载目录和项目中 | 从 GitHub 或本地文件夹导入，集中浏览来源仓库和技能 |
| 收藏越来越多，难以找到合适的工具 | 多级分组、标签筛选和搜索，按自己的工作方式整理 |
| 多个 AI 工具需要同一套技能 | 统一管理共享中心、软件平台和项目目录中的安装关系 |
| 上游更新后，不清楚哪些内容变了 | 检查来源变化，查看结果后再确认同步 |
| 用过的技能容易忘记用途和注意事项 | 阅读文档、记录备注，并关联 Obsidian 笔记 |

## 一个仓库，多处使用

技能仓库保存技能原文件，安装目标按需选择。你可以把常用能力加入共享中心，也可以为某个工具或项目保留专门的技能组合。

```text
GitHub / 本地文件夹
        ↓
     技能仓库
        ├── 分组与标签：整理、查找
        └── 技能安装
              ├── 共享中心
              ├── 软件平台
              └── 项目目录
```

- **集中导入**：从 GitHub 仓库或本地目录收集技能，导入时查看技能清单并处理冲突。
- **按目标安装**：选择软件平台或项目目录，查看技能的安装统计和安装关系。
- **减少重复副本**：共享中心通过链接引用仓库技能；平台安装优先使用链接，必要时回退复制。工具能否读取共享目录取决于其自身支持和配置。
- **适应自己的工具**：配置平台名称与技能路径，管理启用的平台和项目目录。

## 按你的工作方式整理

用分组组织开发、研究、写作等工作场景，用标签描述用途和特点。仓库与技能都可以拖入分组；多级结构、拖拽排序、多选和快捷键适合持续增长的工具库。

浏览时可以切换仓库视图与平铺技能视图，通过名称、描述和备注查找内容。列表列宽、显示列和侧栏可以调整，文档预览与技能清单在同一工作区中查看。

## 跟踪更新，集中处理任务

仓库信息刷新与技能更新检查各有用途：前者刷新元信息、星标数和文档，后者检查技能来源的变化，让你在同步前查看结果。

导入、检查和更新任务集中显示进度与结果。筛选失败项或待处理项后，可以单独重试或批量处理，避免在大量成功记录中逐条寻找问题。

![任务中心：筛选失败项并单独或批量重试](docs/images/product/tasks-zh.png)

技能更新检查按仓库保存进度，支持暂停和继续。程序退出后，重新打开可接着检查未完成的仓库；已完成的仓库不会重复检查。关闭任务窗口后，后台任务继续运行。

## 让使用经验留下来

- **文档阅读**：在详情区查看技能内容和仓库文档。
- **备注与标签**：记录适用场景、使用限制和自己的判断。
- **AI 辅助整理**：生成备注或标签建议，编辑确认后保存；需配置相应 AI 服务。
- **Obsidian 联动**：把较长的实践记录放进笔记库，通过稳定标识关联技能或仓库，便于持续补充。

## 数据由你管理

技能和配置保存在本地，支持本地备份、WebDAV 备份及仓库同步。Windows 便携模式使用 `arsenal.exe` 和同级 `.arsenal` 数据目录，方便保留自己的工具库。

升级前关闭旧程序并备份数据；替换程序时保留已有 `.arsenal`，不要用默认配置覆盖它。远程导入、同步和 AI 功能需要连接对应服务。

## 快速开始

1. 从 [Releases](https://github.com/yufenglyu/Arsenal/releases) 下载适合系统的安装包或便携包。
2. 在“技能仓库”选择“添加技能”，导入 GitHub 仓库或本地技能目录。
3. 创建分组、添加标签，阅读文档并留下备注。
4. 在“技能安装”中配置目标，把所需技能安装到平台或项目。
5. 定期检查更新，通过状态栏“任务”查看进度和处理结果。

可下载的平台与安装格式以 Releases 附件为准。

## 开发与贡献

前端采用 React、TypeScript，桌面应用基于 Tauri 与 Rust。

```bash
pnpm install
pnpm tauri dev
```

`pnpm dev` 可单独启动前端；`pnpm test`、`pnpm typecheck` 和 `cargo test --manifest-path src-tauri/Cargo.toml` 用于验证。构建与打包见 [脚本说明](scripts/README.md)。
