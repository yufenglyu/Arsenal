# 大备份导入与 WebView 内存

## 问题与证据边界

用户报告 macOS 1.5.1 在导入约 800 MiB 的 WebDAV 备份时 WebContent 崩溃，主进程仍然运行。未读取用户备份、远端凭证或本机崩溃报告，不能据此判断实际备份是否完整，也未完成 macOS 实机复测。

源码确认原流程存在两层内存放大：WebDAV 下载返回 `Vec<u8>`，经 JSON 数字数组进入界面，再由 `Array.from` 传回后台；ZIP 解析还同时保存所有解压文件及其 Base64 副本。本地导入通过 `File.arrayBuffer()` 和相同的数字数组 IPC，也有相同风险。

## 新流程

- `restore_webdav_backup` 在后台流式下载到当前配置目录内的私有临时文件，随后直接调用文件恢复流程；界面只传配置和远端相对路径，接收进度和完成结果。
- `import_app_backup_from_path` 接收原生文件选择器返回的路径。界面不读取文件、不生成完整二进制数组。
- ZIP 通过文件句柄读取，每个条目流式复制到私有临时目录的数字文件名。原 ZIP 路径不直接作为解压目标，且检查不安全路径、重复名称、符号链接、大小和 CRC。
- manifest 只保存元数据与暂存文件引用。ZIP 载荷不再转换成全量 Base64；写入目标目录时使用文件复制。暂存引用不参与序列化，也不能从备份 JSON 注入。
- 解析、校验和恢复在阻塞工作线程中执行；网络下载保持异步。现有仓库互斥锁继续保护恢复，既有 Store、目录替换及 linker 安装接口继续负责实际写入。
- 完整 ZIP 下载和所有条目的校验必须先完成，再进入原有恢复流程。下载中断、CRC 损坏和校验失败不会启动恢复；临时下载与解压文件通过 RAII 在成功和失败时清理。
- 删除注册的整包字节导入、下载和导出 IPC 入口，避免界面再次误用。原有文件路径导出入口保持可用；本次没有重构导出与上传的后台内存使用。

## 进度、范围与限制

界面显示“正在下载 / 正在校验 / 正在恢复”。下载每隔约 250 ms 发送已接收字节数和可用的总字节数，不发送文件内容、远端地址、凭证或本地路径。界面关闭或进度接收失败不撤销已经开始的后台恢复。

WebDAV 恢复仍只恢复资源库与集合，本地导入仍支持完整备份；不新增平台路径迁移。ZIP 与 JSON 备份格式不变。ZIP 输入上限 1 GiB、展开总量上限 16 GiB、最多 100000 条目；manifest 与独立 JSON 备份上限 128 MiB。旧 JSON 备份仍在后台解析，但其内存取决于 JSON 元数据大小，不能视为 ZIP 的常量载荷内存路径。

配置目录需要容纳下载文件与解压暂存内容，资源库目标所在磁盘还需容纳恢复暂存目录及旧目录。下载不完整、备份损坏、危险路径、大小限制、磁盘或权限问题分别显示处理建议，不把这些问题笼统归为密码或配置错误。CRC 只用于发现传输/归档损坏，不证明备份来源可信。

原恢复器的语义未改为整份备份的全局事务：通过校验后，实际写入阶段发生磁盘、权限或安装问题时，仍可能已完成部分技能恢复。不能把“导入失败”一概解释为完全没有写入；“尚未开始恢复”的提示仅用于下载或归档校验失败。

## 验证

- 新增真实本地 HTTP 下载与后台恢复测试；注入下载截断和后段 ZIP CRC 错误，验证 Store 与资源库未被更改且临时文件清理。
- 本地导入测试验证仅传文件路径；WebDAV 测试验证只调用一次后台恢复 IPC，不再下载到界面后回传。覆盖进度显示、取消文件选择和错误提示。
- 显式运行 800 MiB 的 Stored ZIP 压力测试：真实 HTTP 下载、磁盘暂存、恢复和逐块内容校验通过，进度消息均小于 256 字节。
- 前端全量 941 项、Rust 全量 649 项通过；18 项按原设置忽略，其中包含需要显式运行的 800 MiB 压力用例。类型检查、lint 与 Clippy 通过。
- 上述单独 Windows debug 测试进程约 8 秒完成；100 ms 轮询记录到峰值工作集约 21.5 MiB、最大观测私有内存约 4.2 MiB。该测量不包含 WebView、整个桌面应用、操作系统文件缓存或 macOS，不能作为跨平台整机内存上限。
- macOS 实际备份完整性与 UI 长时间响应仍需在修复构建上复测。无需再次让旧版界面接收同一个大文件来验证此代码路径。
