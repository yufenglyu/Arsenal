# 仓库来源路径与本地目录

远端来源路径是导入时选中的仓库内 manifest 路径，例如 `skills/demo/SKILL.md`。本地目录只是安装位置，可能因平铺、用户重命名或同名冲突而改变。二者不能互相推断。

## 写入与更新约束

- GitHub 导入将真实 `source_manifest_path` 与技能记录在同一个 Store 事务中提交。重命名和哈希后缀只改变目标目录，不改变来源路径。
- 资源库扫描保留已有来源元数据。仅从磁盘发现的目录可以识别仓库分组，但不生成未经验证的远端路径，也不把仓库名相同的目录认作根技能。
- 检查与应用快照均校验来源路径是否缺失。缺失时返回 `SOURCE_METADATA_MISSING`，不会把无法匹配的本地技能当成远端删除，也不会据此新增或覆盖目录。
- 检查在网络请求前报告元数据缺失。界面明确说明重新检查无法恢复来源，需要重新导入仓库并选择对应技能；不得将其显示为“远端来源已移除”。
- 不根据技能名称、目录哈希或单份文件内容自动重绑定来源；不自动迁移或改写现有记录。

## 回归覆盖

- 磁盘扫描：普通、同名根目录、哈希后缀、重命名及嵌套目录均不推断远端路径。
- 导入与更新：同名技能生成哈希目录、指定本地目录名后，反复扫描仍保留真实路径；后续更新匹配原记录，不误判新增或删除。
- 元数据缺失：检查、预览和应用均停止，原文件保持不变；中英错误提示区分缺失元数据与已移除来源。
