# 统一任务窗口实施

基于已讨论的 `codex/task-flow-redesign` 原型（统一窗口和独立并行重查），正式组件入口为 `src/components/layout/TaskCenter.tsx`。

## 已落实

- 同一窗口展示更新、导入、批量刷新和单仓刷新；各批次可独立展开，关闭和切换标签保留输入。
- 有有效检查快照且无风险的常规更新默认选中，批量选择/排除；固定底栏显示所选范围、需确认和需重查数量。
- 删除、同名新增/删除以及覆盖本地修改在行内核对，单次“允许删除并选中/允许覆盖并选中”授权，不再使用确认勾选框加确认按钮。缺少同步基线的旧数据、修改过的独立复制安装和无法验证本地编辑的仓库文档采用保守确认。
- 同名新增/删除按名称相邻展示原始新旧路径，不自动当成重命名。旧检查结果明确标为失效，仅供查看；失败同步有重查出口。
- 重查立即撤销旧快照确认；按仓库排队和互斥，检查并发上限复用队列的5。网络下载不持有全局镜像锁，本地检查和快照提交保留互斥保护。停止等待真实执行器完成，不提前释放锁。
- 部分仓库重查或执行失败不阻断其他仓库；重试成功覆盖旧错误，即使不可变快照ID相同也不复活旧失败。
- 成功任务主动归档；AI备注和解释不进入窗口。

## 验证

- 类型检查、ESLint通过；全量前端84文件、858项测试通过。
- 全量Rust库测试597项通过、15项忽略；新增本地编辑/上游修改判定回归。
- Vite生产构建通过，保留既有大chunk提示。
- 浏览器使用正式React组件和真实前端队列，后端执行器仅使用隔离的虚构响应：验证两仓库同时检查且其他同步按钮可用、风险单次授权后86→87仓库、导入和更新同时展开。截图为 `task-window-implemented.png`。
- 未将浏览器模拟视为真实GitHub同步或桌面安装验收；本次未发布新版本、未替换便携安装程序。

## 数据边界

真实技能和安装关系仍由已有Store、镜像和linker接口处理。风险确认以快照ID绑定；快照失效或重查后撤销，不将旧确认套用到新结果。界面选择仅存内存，关闭窗口保留，重启后风险项重新确认。
