# JSON 存储迁移操作指南

本工具用于最终 SQLite 版本，以及已核对的早期仓库镜像功能引入前版本，到 JSON v1 格式的离线迁移。工具只使用 Python 标准库中的 SQLite 读取器；应用主程序不依赖 SQLite。按附带 schema 清单校验现有表的列。早期版本仅允许整组缺少六张后续新增的仓库/导入恢复表，并将这些尚不存在的领域初始化为空；未知表、部分缺表或列差异仍拒绝，不猜测结构。

## 迁移前

1. 用旧版应用完成正在运行的导入、仓库镜像和仓库地址迁移，并正常退出所有版本。
2. 备份整个配置目录、外置技能资源库以及其他外置笔记和附件。旧数据库存在 WAL 时，数据库、WAL、SHM 应作为一组保留。
3. 确认配置目录中尚不存在 `store`。不要先启动新版创建空存储。
4. 保留能够读取旧数据的旧版安装程序。配置及资源包含个人数据，不应上传到问题单或日志。

## 执行

在项目根目录运行，路径请替换为实际配置目录：

```powershell
python scripts/migrate-sqlite-to-json.py "D:\Example\.skillshub" --offline-confirmed
```

`--offline-confirmed` 表示操作者已停止应用，不是工具自动停止应用。脚本不读取系统默认目录，也不自动访问实际用户数据。运行时先获取配置目录中的 `.store-access.lock` 排他锁，再创建 `.json-migration.lock`。新版应用使用同一操作系统锁，避免迁移发布与应用启动并发；遗留迁移标记存在时也拒绝启动。锁文件保留在原处，不能通过删除正在使用的锁文件解除占用。

工具先复制数据库及存在的 WAL/SHM 到隔离临时目录，在副本上执行完整性与外键检查。前后比较源文件摘要，拒绝复制期间的变化。它读取 WAL 中已提交的数据，不在源数据库上执行 checkpoint、schema 更新或写操作。

随后转换全部受支持表，保留身份、首次安装时间、托管标记、来源状态、标签、集合、缓存及恢复记录。复合键采用 JSON 数组字符串；布尔值转换为 JSON boolean；仓库笔记解包为完整对象；目录备注中的技能列表转换为数组。笔记的 SQLite 自增序列迁入 `store_counters`，删除过的最高整数 ID 不会被重新分配。

发现待恢复的地址迁移、正在应用或带恢复记录的失败镜像、未知镜像状态、未完成导入文件日志时停止。请返回旧版完成恢复后重试。对于自定义资源库，工具通过 `config.json` 的 settings 路径检查相应导入日志。

所有对象按 SHA-256 命名，写入后重新读取，验证摘要、内容及条目数量。最后在同一配置目录内重命名发布整个 `store`。既有 `store` 不覆盖。旧数据库、配置、技能目录、图标及其他资源保持原样。

## 迁移后验收

- 保存 `store/migration-report.json`；其中只有各表数量和源数据库文件摘要，不包含记录正文。
- 启动新版，检查技能、集合、标签、备注、平台安装关系和仓库笔记，再退出重启验证保存。
- 用一个合成或可恢复的技能验证编辑、安装、卸载、导入、来源更新和备份恢复。
- 保留原始备份直至确认新版工作正常。不要把旧数据库放回运行状态与新版同时写入。

迁移后的编辑只写 JSON。旧程序无法读取这些新增编辑，因此运行旧程序并不等于无损回退。需要回退时，应关闭所有版本，保留当前 JSON 和资源副本，再恢复一致的迁移前完整备份；不能只替换数据库。

## 失败处理

发布前失败不会激活新存储，通常会清理本次临时目录。若发布后的目录刷新失败，可能已经存在有效的新存储；此时应检查 manifest 和摘要，不能直接重跑或删除。异常终止可能留下 `.json-migration-*` 和 `.json-migration.lock`。先确认没有迁移进程或应用运行，再保留失败材料供本地检查；不要直接覆盖或删除已有 `store`。若 `store` 已存在，应先判断迁移是否已完成。

控制台只显示错误类别，避免输出记录内容和敏感路径。需要诊断时在本地查看失败原因，不能把数据库、配置或内容粘贴到公开日志。

原子发布、文件刷新和故障处理已在合成测试中覆盖；真实断电、网络文件系统、所有平台文件系统行为仍需各平台验证。

## 自动化验证

```powershell
python scripts/test_json_migration.py
```

测试使用临时目录合成数据库，覆盖所有表导出、复合键、布尔值、笔记和目录备注转换、已提交 WAL、源文件不变、目标已有拒绝、离线确认、schema 漂移、待恢复状态和模拟磁盘写失败。不会访问真实用户配置。

跨语言验收可运行 `cargo test --manifest-path src-tauri/Cargo.toml python_migration_is_readable_by_native_store -- --ignored`：Python 构造并迁移隔离数据，Rust 用实际 Store 和业务查询验证读取，同时验证 Python 尊重 Rust 持有的目录锁。此项依赖本机 Python，因此默认忽略，发布验收时显式执行。
