# 仓库更新与同步改进修复方案

日期：2026-10-17  
状态：已按确认规则实施；自动化验收记录见第 7 节。

## 1. 已确认规则

远端是唯一权威。同步单位是整个已导入仓库，包含之前未选择导入的全部可识别技能。资源库托管技能的文件集合、路径和字节内容严格对应一次检查锁定的远端提交。

- 远端新增技能全部导入；修改覆盖本地修改；本地托管技能目录中的额外文件移除。
- 远端移除技能时删除本地技能，并通过 linker 卸载明确托管的安装关系。
- 同来源路径保留内部 ID 和本地容器目录；可靠识别的重命名可以保留身份，否则按删除旧技能、新增技能处理，不能凭一删一增推断重命名。
- 本地修改不进入保留或合并流程。旧版本缺少逐文件基准也不阻止镜像，以确认的远端快照直接重建内容。
- 托管复制安装同样以资源库为准，移除额外文件、覆盖本地修改；链接安装继续指向稳定的资源库目录。
- 仓库共享 README 文档统一比较、统一写入一次，不能隐藏在单个技能操作中重复更新。
- 标签、集合、备注等应用管理元数据不属于远端文件镜像；相同技能身份保留元数据，已删除技能清理对应关联。
- 独立本地技能、其他仓库及未托管目录不属于本仓库的覆盖范围。源仓库及本地导入源只读。

这里的整仓指全部受支持布局中的技能及应用管理的仓库共享文档，不是把 .git、构建产物及所有无关仓库文件复制进资源库。

## 2. 检查快照与整仓应用

检查保存不可变提交、版本化摘要、完整候选清单、原有本地身份和报告。应用只接受该快照身份，不重新解析 HEAD。快照缓存缺失时仅重新获取同一提交并校验，无法取得则停止。

每次应用以仓库为单位，包括全部新增、修改、删除及共享文档；页面中的技能明细用于解释变化，不作为跳过部分技能的同步范围。不能将部分更新标为整仓同步成功。

检查后本地编辑仍按远端覆盖，但若技能来源归属或目标路径已被重新分配，必须停止，不能越界覆盖其他对象。仓库任务串行，后端也提供写入互斥。

所有远端内容必须在本地删除前完整获取、验证；404、权限错误、下载失败、截断或无法解析不能解释为空仓库。有效完整快照确实没有技能时允许清理原技能，仍保留仓库跟踪身份以发现后续新增。

过期的旧格式报告不能继续写入，要求重查。新提交留到下一次检查。失败重试继续同一快照，已经一致的内容不重复写入；部分失败明确显示失败，可继续收敛到同一目标版本。

## 3. 写入、恢复与安装关系

复用现有导入事务及 linker，准备好全部技能内容后再替换。恢复资料放在扫描范围外，不把 .bak 留在技能目录。文件系统与数据库不是天然原子事务，必须记录中断状态并支持同一快照重试；不能仅凭内存 Drop 回滚宣称进程崩溃恢复已完成。

保留快照及待处理安装记录，写入完成后核验技能文件、来源身份和安装副本，再标记整仓完成。复制安装失败不能伪装为整仓成功。路径规范化、大小写冲突、目标归属和符号链接边界在写入前检查。

本次不引入恢复区自动永久删除。恢复到旧版是一项独立操作，恢复后会再次被下一次同步覆盖。

## 4. 覆盖统计

检查时冻结本地稳定 ID 清单，每项有唯一去向：已检查、检查失败、未纳入（独立本地、来源缺失、不支持、范围外）。未完成或取消不算无变化。

本地总数 = 纳入检查 + 未纳入检查；纳入检查 = 完成 + 失败 + 未完成。

远端新增不计入检查时本地总数；共享文档、报告行、重试次数不增加技能数。部分重查保留原报告分母，历史检查数量不与当前资源库总数混用。失败仓库必须在覆盖中保留。

## 5. 实施顺序

1. 建立失败回归测试；先提交本方案作为规则基线。
2. 固定快照、整仓应用、取消隐式替换及部分技能同步、共享文档一次写入。
3. 本地严格覆盖、删除清理、复制安装收敛、中断重试与完成校验。
4. 覆盖统计、报告生命周期、错误提示及中英文文案。
5. 隔离测试与构建检查，记录真实桌面测试尚未覆盖的行为。

## 6. 验收场景

- 原来只导入一个技能，远端存在其他技能：同步后全部导入。
- 一删一增但没有重命名证据：两个变化均显示，不隐藏新增或自动配对。
- 检查后远端提交：应用原提交，下次检查发现新提交。
- 本地修改、自建文件、远端删除文件：同步后内容与目标快照完全一致。
- 本地仅安装副本被修改：同步后副本也恢复一致。
- README-only 更新：独立展示，整仓写入一次。
- 远端清空全部技能：删除原技能，后续仍能检查该仓库。
- 请求失败、清单不完整：原内容不作为远端删除处理。
- 链接安装及复制安装：删除清理托管关系，更新保持链接有效。
- 写入中断和确认丢失：重试同一快照，明确恢复或继续完成，不误报成功。
- 本地、来源缺失、失败仓库、新增、重试和部分重查：覆盖统计可对账。

所有删除/覆盖测试使用合成仓库与隔离临时资源库，不操作现用技能数据。

## 7. 实施与验收记录

实现入口：`repository_mirror.rs` 管理检查快照和整仓应用，沿用现有任务队列、GitHub 导入事务与 linker。界面按仓库选择和确认，技能只作为差异明细；旧版逐技能写入 IPC 返回过期错误，避免旧队列绕过新规则。

- 检查保存不可变提交及技能/文档字节，使用版本化 SHA-256 校验；应用不联网解析 HEAD。技能内容上限 128 MiB，快照存储上限 1 GiB；重查替换和清空报告释放不再使用的快照，活动任务引用与中断任务不清除。
- 共享文档独立展示；内容已一致时不重复写入。根目录技能保留嵌套资源；不同插件的同名技能以来源路径生成稳定区分名，避免互相覆盖。
- 本地文件、额外目录和托管复制安装严格镜像。来源路径仅大小写变化保留技能 ID 与本地容器目录；其他无可靠身份依据的变化按删除与新增处理。
- 共享中心可能把同一技能记录标成中心技能。同步前验证其链接确实指向资源库，再恢复资源库主记录并登记中心安装关系，使其纳入检查、更新与删除。
- 替换日志及旧文件位于资源库之外的 `.skillshub-import-*` 目录；同步前内容、安装记录与标签/集合关联另存数据库 `repository_mirror_recovery`。启动先恢复未提交的目录替换；中断的整仓任务可在后续检查或重试时继续同一快照。普通失败不永久阻止重新检查。
- 检查统计保留稳定 ID 覆盖清单，失败与排除原因可展开；部分重查保持原分母，资源库变化显示提示。

自动化验证：前端全量 Vitest 80 个文件、808 项通过；Rust 全量 537 项通过、5 项依赖环境或公网的既有测试按原设置跳过。TypeScript 类型检查、ESLint、Rust Clippy（拒绝 warning）及前端生产构建均通过。构建仍有大于 500 kB 的 bundle 提示；部分既有前端测试输出 React act 提示，但没有失败用例。

新增隔离回归覆盖：选择性导入后整仓补齐、本地编辑/额外文件/空目录清理、复制安装和共享中心链接、远端清空与重复应用、README-only、快照损坏拒写、目录替换中断恢复、根技能嵌套资源、大小写重命名、不同插件同名技能、部分重查统计分母、旧报告拒用和确认身份变化。

未验证：真实桌面人工交互、真实远端仓库端到端同步、macOS/Linux 原生文件系统行为，以及操作系统强制断电。恢复测试模拟中断阶段，不等同于硬件断电验证。恢复资料目前用于诊断与恢复，尚无可视化恢复管理入口。
